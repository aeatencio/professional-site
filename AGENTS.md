# SITE-V1 repository agreement

- Build Andrés Atencio's public professional site and CV around the identity
  `Software Developer · IT Teacher`.
- Treat R1, R2 and R3 as cumulative, incremental and verifiable releases.
- Use `npm run dev`, `npm run check`, `npm run build` and `npm run preview`.
- Treat every commit, not only the current tree, as potentially public. Do not
  add internal data merely because the remote is currently private.
- Accept professional facts only through an approved, versioned public
  projection. Never copy facts directly from chats, draft copy, or visual
  references; they may propose information but cannot make it canonical.
- Do not add private evidence, internal locators, open questions, disputed or
  unapproved facts, internal editorial notes, evidentiary documents, secrets, or
  unnecessary personal data.
- Never access, clone, mount, or query `professional-source` during build, test,
  preview, or deploy. The public build must remain self-contained.
- Site and CV are separate representations of shared approved facts and may use
  different copy. Never invent professional facts.
- Preserve existing and unrelated work. Inspect changes before editing.
- Keep page content complete and usable independently of the decorative cable.
- SITE-V1 has no public visitor-facing AI.
- Do not change repository visibility, push, deploy, or publish without explicit
  human authorization. Repository opening and site deployment are independent.
- Do not introduce React, a backend, CMS, database, authentication or a custom
  API. Add GSAP, ScrollTrigger, Playwright or Vitest only in the release where an
  established requirement justifies them.
- Before closing an increment, run applicable checks and build, inspect every
  changed or untracked file, and review Git status and diff diagnostics.
